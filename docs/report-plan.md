# แผนรายงาน PAM สำหรับผู้บริหาร

รายงานอ่านข้อมูลจริงจาก PAM ฝั่ง Next.js server ทุกครั้งที่เปิดหน้าและกดดึงใหม่ ไม่มีจำนวนหรือชื่อผู้ใช้จำลอง ไม่ใช้ไฟล์ snapshot เป็นแหล่งข้อมูล เก็บ Client Secret และ Token ฝั่ง server เท่านั้น

## หน้ารายงาน A4

ปรับรายงานหลักเป็น 5 กลุ่มหน้า: ภาพรวมผู้บริหาร, ทะเบียนทรัพยากรพร้อมประเภท/สถานะ/ผู้ได้รับสิทธิ์, Users พร้อมบทบาท, Groups พร้อมภาพรวมสิทธิ์ดูข้อมูล, รอบรายงานและประเด็นติดตาม ตารางยาวแยกหน้าต่อ และภาคผนวก HTTP/Endpoint เลือกเพิ่มได้ ไม่พิมพ์เป็นหน้าแยกสำหรับทุก API ที่ล้มเหลว

1. **ภาพรวม:** จำนวน Users และ Groups ตาม API, จำนวน Resources เมื่อดึงได้, สถานะความครบถ้วน และข้อจำกัดในการใช้ข้อมูลตัดสินใจ
2. **ผู้ใช้:** Username, ชื่อ, Email, Role, สถานะล็อก และค่า 2FA ที่ API ส่งมา ไม่ตีความค่าที่ไม่รู้จักว่าเปิดหรือปิด
3. **บทบาท:** บทบาทที่แนบมากับ Users และสมาชิกที่พบ จำนวนนี้ไม่ใช่ Roles ทั้งหมดในระบบ
4. **กลุ่ม:** ชื่อกลุ่ม แหล่งที่มา จำนวนสมาชิก และชื่อสมาชิกจากการจับคู่ Group.users กับ User.id พร้อมจำนวนรายการทรัพยากรที่แนบมากับกลุ่ม
5. **ทรัพยากร:** รายการ Resources และประเภทเมื่อ API ส่งกลับมา ข้อมูลที่ดึงไม่ได้แสดงเป็นไม่ทราบ ไม่แสดง 0 แทนจำนวนทั้งระบบ
6. **ภาคผนวก:** Endpoint, HTTP status และผลการตรวจ GET สำหรับทีมระบบ ไม่ใช้ผล GET ยืนยันว่า POST/PUT/DELETE ใช้งานได้

รายการยาวแยกหน้าต่ออัตโนมัติ พิมพ์เป็น PDF และดาวน์โหลด JSON ที่ปิดบังฟิลด์ลับได้โดยผู้ใช้กดเอง

## แหล่งข้อมูลที่ตรวจพบ

- Users: `/pam/apps/users/user/?page=1&page_size=100&search=&filter_by=` — รายการ `results`, จำนวน `count`
- Groups: `/pam/apps/groups/groups/?page=0&limit=100&search=&filter_by=` — รายการ `groups`, จำนวน `totalGroups`; เริ่มหน้า 0
- Resources: `/pam/apps/resources/?page=0&limit=100&search=&filter_by=` — ยังตอบ 500 ณ การตรวจครั้งนี้
- Roles/Assets/System User/Groups/Application endpoint ตามเอกสารยังตอบ 500 สำหรับคำขอที่ทดสอบ
- Tickets: `/ticket/ticket/` ตามเอกสารตอบ 404; `/ticket/tickets/` ที่พบในโค้ดหน้าเว็บตอบ 500
- System User list และ Certificates ตอบ 403

## ผลตรวจเพิ่มเติมจากหน้าเว็บจริง

หน้า All Resources เรียก `/pam/apps/resources/?page=0&limit=10&search=&filter_by=` ได้ HTTP 200 ใน session ของผู้ใช้ที่ล็อกอิน แต่ URL และพารามิเตอร์เดียวกันใช้ Client Credentials ตอบ 500 จึงต้องแยกการรองรับ OAuth ออกจากการเข้าถึงผ่านหน้าเว็บ ไม่คัดลอก browser session token ไปใช้ในรายงาน

Asset detail ใช้ `/assets/asset/?asset_id=<id>&is_clone=false` และ Application detail ใช้ `/apps/app/?app_id=<id>&is_clone=false` ตอบ HTTP 200 เมื่อใช้รหัสจริงที่อ่านจาก Resources Response พบและทดสอบสำเร็จ 7 Assets และ 2 Applications รายการเหล่านี้ยังไม่ใช่การยืนยันรายการครบทั้งระบบ

Group detail ใช้ `/groups/group/?group_id=<id>` ตอบ 200 ส่วน `/ticket/ticket-routing/` ตอบการตั้งค่า `use_ticketing_automation` ได้ แต่ไม่ได้ส่งรายการ Tickets มา WebApp detail ที่ทดสอบตอบ 403

รายงานรับรหัสที่เลือกผ่าน query `assets`, `applications`, `webApps` ซึ่งแก้ได้ในแถบเครื่องมือ แต่ละค่าคั่นด้วย comma ไม่เกิน 50 รหัสต่อประเภท ทุกครั้งที่เปิดหน้า/refresh จะดึงรายละเอียดจาก API ใหม่ ไม่ฝังรายการรหัสหรือชื่อทรัพยากรลง source code และไม่อ่านไฟล์ snapshot หาก API รายการรวมกลับมาใช้ได้ จะค้นหารหัสจากรายการสดโดยอัตโนมัติด้วย

เพิ่มหน้ารายละเอียด Assets/Applications ตามข้อมูลที่ดึงได้ และแยกภาคผนวกหลายหน้าเมื่อผลตรวจมีจำนวนมาก

สมาชิกกลุ่มจับคู่ได้จากรหัสที่ส่งกลับ แม้ endpoint assigned-users ตอบ 403 รายการ assets/apps ที่ว่างในกลุ่มไม่ยืนยันว่าไม่มีทรัพยากรทั้งระบบ ไม่ใช้สมาชิกกลุ่มหรือสิทธิ์เข้าถึงระบุผู้รับผิดชอบเครื่อง

## ขั้นตอนเพื่อให้รายงานทรัพยากรครบ

1. ให้ผู้ดูแล PAM ตรวจ backend log ของ Resources 500 และยืนยัน schema/query ของ endpoint สำหรับรุ่นที่ติดตั้ง
2. ยืนยันการรองรับ OAuth Client Credentials ของ endpoint รายการและการจัดสรร; scope ใน Token ไม่ยืนยันว่า endpoint ทุกตัวรองรับ
3. เมื่อรายการ Resources สำเร็จ ดึงทุกหน้าและตรวจ received เทียบ total_resources รายงานตรวจข้อมูลการจัดสรรของ Asset/App ที่ได้รับรายละเอียดจริงอยู่แล้ว แม้รายการรวมยังล้มเหลว
4. System Users และ Certificates ต้องตรวจสาเหตุ 403 ก่อนเพิ่มสรุปข้อมูล ไม่ใช้ข้อมูลสมมติ
5. หากต้องรายงานผู้รับผิดชอบ ต้องมี field หรือทะเบียนผู้ดูแลโดยตรง สิทธิ์การเข้าถึงอย่างเดียวไม่เพียงพอ

## เครือข่ายและ Token

PAM resolve เป็น 10.20.2.33 จากเครื่องปัจจุบัน เครื่องที่รัน Next.js ต้องเข้าถึง DNS/HTTPS ของ PAM ผ่านเครือข่ายองค์กรหรือ VPN การเปิดรายงานจาก Wi-Fi อื่นทำได้ถ้าเข้าถึงเครื่องรายงานได้และเครื่องรายงานยังเข้าถึง PAM ได้ ไม่ยืนยันว่ามีทางเข้า PAM จากอินเทอร์เน็ตสาธารณะ

ขอ Token อัตโนมัติจาก Client ID/Secret/Customer โดย Token ตอบอายุ 60 นาที ใช้ header Authorize ตามเอกสาร ใบรับรองใช้การตรวจ fingerprint ที่กำหนดไว้ หากเปลี่ยนใบรับรองต้องตรวจ fingerprint ใหม่ หรือใช้ CA ขององค์กรที่เชื่อถือได้

อ้างอิง: https://www.miniorange.com/pam/admin-docs/client-credentials

## ข้อมูลเพิ่มเติมที่รวมในรายงานสด

- ประเภททรัพยากรและค่า active นับจากรายละเอียดที่ดึงสำเร็จ แยกจากจำนวน Resources ทั้งระบบและสถานะออนไลน์
- ความสามารถตามหมวดใน role.capabilities นับค่า boolean จริง ไม่ใช้แทน OAuth scope หรือการจัดสรรเครื่อง
- ผู้มีสิทธิ์ของแต่ละ Asset/App ตรวจ endpoint allocated-users จากรหัสในรายละเอียดที่ยืนยันแล้ว ผล 403/500 แสดงว่าไม่ทราบ ไม่สรุปว่าไม่มีผู้ใช้
- Roles, System Users, Tickets และ Certificates มีหน้าผลตรวจแยก เก็บ JSON ที่ปิดบังข้อมูลลับใน response รายงานเมื่อดึงได้ ไม่เก็บลงไฟล์อัตโนมัติ รายการหมวดเพิ่มเติมยังไม่ยืนยันครบทุกหน้า
- Resources ใช้ query page=0&limit=10 ตามหน้าเว็บจริง และ pagination ใช้ขนาดหน้าจาก query ไม่หยุดหลังหน้าแรกเพราะถือว่าต้องมี 100 รายการ

## การค้นหาเพิ่มเติมและรายเดือน

ค้นหา Asset/App แบบ GET ราย ID 1–1000 แล้ว พบ 7 Assets และ 2 Apps โดย ID ใน response ตรงกับคำขอ ไม่มีทรัพยากรที่ยืนยันได้เพิ่มในช่วงนี้ ผล 400/404 หรือไม่ตรง ID ไม่ถูกนับเป็นทะเบียน ยังยืนยันรายการทั่วระบบไม่ได้เพราะ Resources รวมตอบ 500 ช่วงค้นหาเริ่มต้นในหน้ารายงานเป็น 1–100 เพื่อให้โหลดเร็วขึ้น และปรับได้ถึง 1000 หรือปิดด้วย 0; 1–1000 ใช้ประมาณ 86 วินาทีในรอบตรวจจริง

พบ Audit API GET `/pam/apps/audits/generate-reports/` ใน JavaScript หน้าเว็บ ใช้ report_type ของการจัดสรร User/Group/Role, response_type=table, page/page_size และ time_zone ทั้งสามแบบยังตอบ 403 ผ่าน OAuth ไม่ยืนยันตัวกรองช่วงวันที่หรือข้อมูลย้อนหลัง รายงานให้เลือกรอบเดือนเพื่อจัดทำเอกสารสถานะปัจจุบันเท่านั้น ไม่กรองทะเบียนย้อนหลัง ไม่สร้างยอดกิจกรรม/แนวโน้มรายเดือนจนกว่าจะดึง Audit ตามวันที่และ pagination ได้จริง
